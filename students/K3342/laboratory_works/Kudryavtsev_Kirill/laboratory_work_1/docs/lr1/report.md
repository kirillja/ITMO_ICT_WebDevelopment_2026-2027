Команды выполняются из папки `laboratory_work_1`. Сервер и клиент запускаются в отдельных терминалах.
`Ctrl+C` останавливает сервер.


## Задание 1 Обмен сообщениями по UDP

Сервер создаёт `socket(AF_INET, SOCK_DGRAM)`, привязывается к адресу через
`bind()` и получает сообщение через `recvfrom()`. Вместе с датаграммой он
получает адрес отправителя, которому отвечает через `sendto()`.

Клиент отправляет строго `Hello, server`. Сервер выводит эту строку и возвращает
`Hello, client`, которую выводит клиент. UDP не гарантирует доставку; клиент
ждёт ответ не более пяти секунд. Вызов UDP `connect()` выбирает адрес
получателя, но не устанавливает TCP-соединение.

```sh
python3 -m task1.server
python3 -m task1.client
```

Результат обмена:

```text
Сервер: Hello, server
Клиент: Hello, client
```

## Задание 2 Теорема Пифагора через TCP

По номеру 13 получен вариант 1. Клиент считывает два катета с клавиатуры;
сервер вычисляет гипотенузу `c = sqrt(a² + b²)` с помощью `math.hypot(a, b)`.
Функция `hypot` уменьшает риск переполнения промежуточных квадратов.

Используется `SOCK_STREAM`. Сервер вызывает `listen()` и `accept()`, клиент —
`create_connection()`. Запрос — JSON в UTF-8, завершённый переводом строки:

```json
{"a": 3.0, "b": 4.0}
```

Успешный ответ:

```json
{"ok": true, "result": {"a": 3.0, "b": 4.0, "c": 5.0}}
```

TCP передаёт поток байт, поэтому один `recv()` не определяет сообщение целиком.
`readline()` читает до `\n`, даже если запрос пришёл несколькими частями.
Длина запроса ограничена 4096 байтами. Сервер отвергает отрицательные,
нулевые, нечисловые и бесконечные значения. В ответе об ошибке возвращается
`ok: false` с объяснением. Клиент также проверяет ввод и допускает десятичную запятую.

```sh
python3 -m task2.server
python3 -m task2.client
```

```text
Первый катет a: 3
Второй катет b: 4
Гипотенуза c = 5
```

## Задание 3 Отправка HTML через HTTP

Сервер загружает `task3/index.html` как байты при запросе `GET /` или
`GET /index.html`. Путь определяется относительно файла сервера, поэтому
выбор рабочей директории не влияет на поиск HTML.

Ответ строится вручную: строка статуса, заголовки, пустая строка, тело.
Строки заголовков разделены `\r\n`, конец заголовков — `\r\n\r\n`.
`Content-Length` равен числу **байт**, а не символов HTML.
`Content-Type: text/html; charset=utf-8` позволяет отображать русский текст.
`sendall()` отправляет всё сообщение, после ответа соединение закрывается.

```sh
python3 -m task3.server
curl -i http://127.0.0.1:9003/
```

В браузере открыть [локальную страницу](http://127.0.0.1:9003/).
Неизвестный путь возвращает 404, метод кроме GET — 405 с `Allow: GET`.

## Задание 4 Многопользовательский TCP-чат

Сервер хранит словарь активных соединений и создаёт
`threading.Thread(target=chat.handle, ...)` для каждого клиента. Один и тот же
`task4/client.py` запускается независимо любым количеством пользователей;
имена вводятся с клавиатуры и не зашиты в отдельные клиентские файлы.

Имя занимает от 1 до 32 символов. Сервер проверяет уникальность без учёта
регистра: `Alice` и `alice` считаются одним именем. Первая строка клиента —
имя, последующие строки — сообщения. Команда `/quit` выводит `BYE` и завершает
участие. EOF и обрыв соединения также удаляют клиента и освобождают имя.

| Префикс | Назначение |
| --- | --- |
| NAME | Запрос имени |
| OK | Подтверждение входа |
| ERROR | Некорректное или занятое имя, слишком длинное сообщение |
| MSG | Имя отправителя и текст сообщения |
| SYSTEM | Уведомление о входе или выходе |
| BYE | Подтверждение выхода |

Сервер рассылает сообщение всем остальным участникам. Блокировка `self.lock`
защищает список клиентов. Для рассылки создаётся копия списка, после чего
общая блокировка освобождается. У каждого клиента есть отдельный `send_lock`,
чтобы разные серверные потоки не смешивали байты сообщений одному получателю.
Клиент использует отдельный поток получения, поэтому видит сообщения,
пока основной поток ждёт ввод с клавиатуры.

```sh
python3 -m task4.server
# В трёх разных терминалах:
python3 -m task4.client
```

Например, Alice отправляет `Привет`, Bob и Кирилл получают `MSG Alice: Привет`.
При `/quit` от Bob остальные получают `SYSTEM Bob вышел из чата`.

## Задание 5 Журнал оценок через GET и POST

HTTP реализован через `socket`, без `http.server`, Flask или Django.
Парсер читает заголовки до `\r\n\r\n`, затем дочитывает тело по
`Content-Length`. Ограничения: 16 КиБ заголовков, 64 КиБ тела, пять секунд
ожидания. Поддерживается одно обращение на соединение, без chunked transfer.

Журнал хранится как `dict[str, list[int]]`, поэтому все оценки одного предмета
находятся в одной записи:

```json
{"Математика": [5, 4], "Веб-программирование": [5]}
```

Данные сохраняются в JSON-файл атомарной заменой временного файла. После
перезапуска оценки подгружаются. Хранилище не включается в Git.
Сервер последовательно обрабатывает HTTP-подключения, поэтому операции с
журналом не выполняются одновременно. Одновременно запущенные серверы
должны использовать разные файлы данных.

| Метод | Путь | Входные данные | Результат |
| --- | --- | --- | --- |
| GET | `/` или `/grades` | Нет | 200, таблица оценок и HTML-форма |
| POST | `/grades` | `subject`, `grade` в HTML-форме | Сохранение и 303 на `/grades` |
| Другой метод | Известный путь | Любые | 405 и заголовок Allow |
| Любой | Неизвестный путь | Любые | 404 |

HTML-форма отправляет `application/x-www-form-urlencoded`. Дисциплина должна
содержать 1–100 символов после удаления пробелов по краям, оценка — целое
число от 1 до 5. Ошибки данных возвращают 400, неподдерживаемый тип тела —
415, отсутствие Content-Length у POST — 411. Названия экранируются через
`html.escape()`, поэтому пользовательский HTML отображается как текст.

```sh
python3 -m task5.server
curl -i -X POST http://127.0.0.1:9005/grades \
  --data-urlencode 'subject=Математика' --data 'grade=5'
curl -i -X POST http://127.0.0.1:9005/grades \
  --data-urlencode 'subject=Математика' --data 'grade=4'
curl http://127.0.0.1:9005/grades
```

В браузере открыть [журнал оценок](http://127.0.0.1:9005/).
После двух запросов в строке «Математика» показаны оценки `5, 4`.

## Результаты и ограничения

[Пять интеграционных проверок](testing.md) прошли на Python 3.13.
Они используют реальные процессы и сетевые соединения. Проверены три
одновременных клиента чата, повторное имя, выход, передача TCP-запроса частями,
сохранение журнала и экранирование HTML. [Полный исходный код](source.md)
позволяет сопоставить реализацию с описанным протоколом.

Это учебные локальные серверы. HTTP не поддерживает keep-alive, TLS и
Transfer-Encoding. Чат не хранит историю и не аутентифицирует пользователей;
его имя служит идентификатором участника. Медленный получатель может
задержать отправку своего сообщения. Если сервер чата отключился во время
ожидания `input()`, клиент сообщает об этом; для завершения ввода нажмите Enter.
